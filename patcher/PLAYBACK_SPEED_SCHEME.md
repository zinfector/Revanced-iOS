# Native speed menu on first launch

Local native code proves the rate and model menu delegates call separate player setters. YTLocalPlaybackController.setPlaybackRateModel: ignores writes in intermediate states and preserves native clamping when active. The previous patcher restored a remembered/default rate asynchronously after data load and remembered every float setter, including native initialization. Those paths could supersede a menu intent or remember initialization rather than a user choice. Their contribution to the reported first-launch symptom is not yet device-confirmed.

Version 0.3.17 tracks the exact native overlay manager's player from its initializer, captures explicit native rate/model menu choices, invalidates queued default restoration, and preserves the complete selected model. Native setters and limits remain authoritative. Four bounded retries (0/100/350/1000 ms) apply only while the same ordinary content is current; native active-rate observations confirm completion. Video changes cancel old requests. Autospeed/unsupported rates stay native without retry. Default restoration occurs once per content binding and cannot supersede an explicit choice. The Video tools speed chooser uses the same intent path.

Full Hook diagnostics includes playback_speed: source, gate, explicit_native_choice, native_choice_count, apply_attempts, requested_rate, native_rate_available and native_observed_rate. native_rate_confirmed establishes the observed native rate, not a media timing measurement. No credentials/video IDs are included. No tests run; device confirmation pending.

## 0.3.18 granular command bridge

Report 728 before and after reload shows zero legacy-menu callbacks even when the native observed rate becomes 1.25. The slider uses YTPlayerBlockImpl.setPlaybackRate:error: / setPlaybackRateModel:error:, and its getter/model and event-center methods. Local decompilation proves initWithContext: captures a weak player once; retrievePlayerOrFailWithError: returns nil with an error when that player is missing. Getter output then contains no rate; setters do not apply. This startup hazard is statically proven but is not yet proven to be the device failure.

Scope recovery to those five synchronous main-thread bridge methods. When the native retrieval returns nil, require a loaded watch in a window whose actual player owns the current ordinary content and matches the current playback controller. Return that actual player just for the scoped call. Keep every non-nil native owner, background call, other API and failed ownership check native. No ivar writes or global player substitutions. Preserve native event-center creation, writers, limits and scalar models. Capture granular choices at the native player model setter so initialization writes are never remembered.

playback_speed.command_bridge shows block creations, missing initial players, getter/selection calls, native retrieval failures, successful visible-watch recoveries, rejected recovery, event subscriptions, argument rate/scalar, result availability/rate and native errors. Missing picker callbacks, a missing bridge player, empty initial model, native clamping and a rejected scope can now be distinguished. No tests run; device confirmation pending.

## 0.3.19 overlay initialization and checkpoint history

Report 755 first launch uses the legacy overlay route; reload uses the command bridge. Neither report exercises a missing player. Native overlay getters and setters traverse the varispeed controller and its delegate; the manager reads a cached active video, not the current player directly. Seed that cache through its native state update method when missing/stale and at picker opening, guarded to the exact current ordinary-content player. Recover only absent/invalid native rate reads and nil models. Capture overlay intent before native forwarding so a nil intermediate delegate cannot swallow it. Preserve native limits and automatic scalar models. This is a targeted fix for a statically identified initialization hazard; its role in the device symptom remains unconfirmed.
