# Native speed menu on first launch

Local native code proves the rate and model menu delegates call separate player setters. YTLocalPlaybackController.setPlaybackRateModel: ignores writes in intermediate states and preserves native clamping when active. The previous patcher restored a remembered/default rate asynchronously after data load and remembered every float setter, including native initialization. Those paths could supersede a menu intent or remember initialization rather than a user choice. Their contribution to the reported first-launch symptom is not yet device-confirmed.

Version 0.3.17 tracks the exact native overlay manager's player from its initializer, captures explicit native rate/model menu choices, invalidates queued default restoration, and preserves the complete selected model. Native setters and limits remain authoritative. Four bounded retries (0/100/350/1000 ms) apply only while the same ordinary content is current; native active-rate observations confirm completion. Video changes cancel old requests. Autospeed/unsupported rates stay native without retry. Default restoration occurs once per content binding and cannot supersede an explicit choice. The Video tools speed chooser uses the same intent path.

Full Hook diagnostics includes playback_speed: source, gate, explicit_native_choice, native_choice_count, apply_attempts, requested_rate, native_rate_available and native_observed_rate. native_rate_confirmed establishes the observed native rate, not a media timing measurement. No credentials/video IDs are included. No tests run; device confirmation pending.
