# Watch-scoped dislike layout compatibility

The user confirmed that disabling the old `first_launch_ui` policy restores the You page but breaks dislike presentation. Report 235 (0.3.36) shows that the policy replaced a 44,341-byte native cold group with an empty group and suppressed native template context before any visible watch was observed. This establishes the cross-screen regression in the old policy; the replacement below still needs device verification.

The existing preference key is retained, with the label **Use compatible dislike layout**. Its startup enablement still requires RYD and paired vote buttons. Native blob loading now returns the original group unchanged. Active configuration/data/hash getters and the template-context getter default only during a verified watch operation. Native speed/registry reads retain precedence within those operations.

`RVVoteFirstLaunchScopes.inc` establishes temporary thread-local scopes at watch request construction, the two native context factories, watch controller/results construction, and watch response/model consumption. The action-bar filler producers also enter a scope while materializing and normalizing native vote elements. Every scope saves its prior depth and restores it in `@finally`; no scope survives asynchronous work. The asynchronous watch response is handled at its native UI/model consumer, rather than by changing callback arguments or globally toggling policy while a video is open.

Both context factories select watch scope by the actual service type. Native `YTPlayerRequestFactoryImpl.requestForPlayerWithPlayerRequest:URLRequestProperties:enablePlayerResponseCacheKeyRelaxation:playerResponseCacheToken:skipInnertubeCacheLookup:` (`0x1010336e4`) uses **0x73**; native `YTWatchNextServiceImpl.makeRequest:refresh:retryEnabled:timeoutInterval:responseBlock:errorBlock:` (`0x1019882b0`) uses **0xa1**. Other services suspend an enclosing scope during context construction, so browsing while a player exists does not strip the browse template context.

The supplied database also verifies that `YTELMInnerTubeContextDecoratorImpl.decorateContext:` (`0x100251608`) and its account-scoped counterpart (`0x100304a38`) read `emlTemplateServingContext` and assign it to the outgoing client. These decorators execute inside the respective native context factory methods, after client-info construction. Scoping only `clientInfoWithSendDeviceIdentifier:serviceType:` would therefore end too early.

The seven new hooks were compared with the extracted Objective-C method encodings and implementation addresses. The checked metadata is included in `profiles/literal-hook-metadata.json`; the full hook checker reports zero mismatches. Settings catalog validation passes. No native compilation, IPA packaging, CI build or device test was performed.

Diagnostics identify the change as `watch-vote-scope-1`, report native group/context preservation separately from scoped defaults, and retain paired-template/materialization checkpoints. Missing required scope hooks disable the compatibility policy rather than falling back to the old global policy.

After installing a build containing this change, enable **Use compatible dislike layout** and fully restart. Verify the You page on cold launch, dislikes on the first and subsequent videos, refresh, account browsing with a watch/miniplayer open, and a subsequent app launch. Capture a report if either presentation fails. The saved preference remains false if it was disabled during isolation; the implementation does not override that choice.
