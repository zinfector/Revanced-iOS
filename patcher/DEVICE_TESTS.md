# Device verification: iPhone 17 Pro Max / iOS 27.0

This is the user-reported target. A supplied device screenshot shows the app reaching Google account authentication and Google rejecting sign-in. The 0.3.1 auth IPA installed and all authentication hooks ran, but account login was rejected; storage repeatedly reported missing entitlements. The user subsequently reported successful login. Playback, refresh and other feature behavior have not been verified, and no device connection or installed signature inspection is available in this Windows workspace. See [AUTHENTICATION_SCHEME.md](AUTHENTICATION_SCHEME.md) for the native SSO analysis and revised 0.3.2 adapter; successful login is user-reported; refresh and persistence remain unverified.

## Install and collect evidence

1. For SideStore, use the separately generated `output/YouTube-21.39.4-RVPort-0.3.7-SideStore-auth-unsigned.ipa`, which uses the cloud-built native payload and removes extensions. Other signing workflows can use `output/YouTube-21.39.4-RVPort-0.3.7-expanded-unsigned.ipa`. Re-sign with your installation/signing workflow. It must sign the main app, `Frameworks/RVPort.dylib` and retained extensions. If that workflow cannot retain extensions, make a separate output with `--strip-extensions`. Signing can rename the bundle ID; preserve the YouTube executable name, app version and Mach-O UUID used by the runtime profile.
2. Launch the app and record whether it reaches the feed and plays an ordinary video. A launch failure requires the iOS crash log, including exception, termination reason and loaded-image list, before diagnosing any feature.
3. Hold three fingers for one second. Open **Show hook diagnostics**, then **Copy diagnostic report**. Save the report with profile acceptance, effective configuration and installed/skipped/missing hooks. A static metadata match is not evidence that installation succeeded on the device. **Copy patch configuration** exports settings that the Windows GUI can load.
4. Use the switches to test individual features. A changed response/request feature may need a reopened video or app restart. Existing saved in-app preferences override the shipped JSON defaults.
5. Record results in `build/device-results-template.json`, changing `pending` only after observing the behavior. Include video type, feature state, reproducer and diagnostics for failures.

## Authentication experiment

The auth IPA enables both `sideload_auth_identity` and `sideload_auth_keychain`. Attempt login, then check an authenticated operation and cold relaunch. For 0.3.2, verify `private_keychain_enabled` is true, auth-request body identity checks match, and keychain reads no longer fail with `-34018`. Successful reads can return 0; a fresh account/state item can legitimately return not-found (`-25300`). The old `keychain_probe` event should be absent. Record baseline/identity-only/keychain-only/both outcomes, restarting after changing the switches. Copy the diagnostic report after any failure; the `authentication` section contains redacted events and numeric statuses. A server error page can remain inside the system browser without returning an error to the app, so a cancellation alone cannot identify Google's error. Test token refresh and an ordinary SideStore refresh using the same signing identity. Do not mark login successful from launch or browser opening alone.

## SponsorBlock repair in 0.3.5

The 0.3.4 report shows SponsorBlock/markers enabled and hooks installed, but the user observed neither markers nor skips on `https://www.youtube.com/watch?v=Ke_iFvL0A1c`. A prior read-only service request returned four segments: intro 49.312-56.312, self-promotion 56.179-73.447, sponsor 382.982-464.851, and outro 464.707-481.021 seconds. With the reported policy, the automatic ranges are 49.312-73.447 (merged overlap) and 382.982-464.851; outro is marker-only. Service data can change.

The update adds the native player event-center clock and canonical controller/overlay binding. No local, cloud, or device tests were run for 0.3.5 at the user request. If the behavior still fails after installing the new IPA, copy Hook diagnostics while that video is playing. The `sponsorblock` section exposes controller/overlay binding, clock counts, playback gate, HTTP status and network error code, accepted segments, requested seeks and drawn marker rectangles without video IDs, URLs, CPNs or credentials. `seek_requested` records a native request, not confirmed playback completion.
